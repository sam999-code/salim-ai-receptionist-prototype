# Salim AI Receptionist — learning prototype

**الحالة الحالية:** نموذج تعليمي محلي لاستقبال WhatsApp Webhook وصياغة ردود تجريبية. لا يرسل الردود إلى العملاء، ولا يجري مكالمات، ولا ينشئ حجوزات حقيقية. وضع `--smart` يستخدم Anthropic API إذا زُوّد بمفتاح عبر بيئة التشغيل؛ قد يسيء فهم الرسائل، ولذلك لا يصلح بعد لخدمة عملاء حقيقية. راجع [البحث والتصميم متعدد الطبقات](AGENT_RESEARCH_BLUEPRINT_AR.md) و[خطة التطوير المختصرة](ARCHITECTURE_ROADMAP.md) لما بُني وما بقي.

**الأسرار:** لا توجد مفاتيح حقيقية في ملفات هذا المستودع. أدخلها في نافذة PowerShell عند التشغيل فقط، ولا تضعها في الكود أو لقطات الشاشة أو Git. ملف `.gitignore` يستبعد ملفات الأسرار المحلية؛ افحص أي ملف جديد قبل نشره.

هذه نسخة تدريبية **تعمل محليًا دون حساب أو API key**. لا تجري مكالمات ولا ترسل رسائل حقيقية. هدفها أن ترى منطق المساعد قبل توصيله بالهاتف.

## التشغيل

افتح `Terminal` داخل هذا المجلد ثم نفّذ:

```powershell
python app.py
```

اختر `1` لتجربة مكالمة عميل محتمل: يرحّب المساعد، يسأل عن الاسم ووسيلة التواصل ونوع المشروع والتفاصيل، ثم يعرض ملخصًا لسليم. الملخص يقترح متابعة العميل بوسيلة التواصل التي قدّمها؛ لا يَعِد المساعد بسعر أو موعد تنفيذ.

إذا قال العميل `I don't know` أو `not sure` أو ترك الإجابة فارغة، سيطرح المساعد **سؤالًا مختلفًا واحدًا فقط**. إذا بقيت المعلومة غير واضحة، يسجل `Not provided` ويتابع بدل تكرار السؤال. إذا لم يعطِ العميل وسيلة تواصل، يوضح الملخص أن المتابعة غير ممكنة بعد. هذه قواعد محادثة تدريبية بسيطة، وليست فهمًا كاملًا لكل تعبير لغوي.

اختر `2` لتجربة مكالمة حجز صادرة. مثالنا: `Riviera Royal`، التاريخ `2026-10-30` (الجمعة)، الوقت `20:00`، وعدد الأشخاص `3`. يحتاج البرنامج تاريخًا محددًا، لأن كلمة “Friday” وحدها قد تعني هذا الأسبوع أو الأسبوع القادم. سترى الجملة التي سيقولها المساعد للمطعم ثم تلعب دور المطعم باختيار النتيجة. لن يُظهر البرنامج `CONFIRMED` إلا بعد إدخال رد تأكيد من المطعم.

إذا اخترت `Confirmed` أو `Alternative offered` لكن رد المطعم غير واضح، سيطلب المساعد التوضيح مرة واحدة. إن بقي غير واضح، تصبح الحالة `UNVERIFIED`، ولا يدّعي وجود حجز.

## الفكرة الأساسية

`Request` هو ما طلبته أنت. `Outcome` هو ما قاله الطرف الآخر فعلًا. `Update` هي الرسالة التي سيعود بها المساعد إليك. لا يجوز تحويل `Request` إلى `CONFIRMED` من تلقاء نفسه. في حالة `alternative` لا نثبت الموعد الجديد قبل موافقتك عليه.

في الدروس اللاحقة يمكننا إضافة فهم اللغة الطبيعية، ثم الاتصال الهاتفي الحقيقي ورسالة التحديث، مع اختبار كل خطوة قبل تفعيلها.

للتأكد من منطق النسخة الحالية:

```powershell
python -m unittest -v
```

## Lesson 2: استقبال WhatsApp Webhook محليًا

عندما ترسل رسالة `Hi` إلى رقم الاختبار، تظهر في صفحة Meta. لكي تصل إلى **برنامجنا**، يجب أن ترسل Meta حدث `Webhook` إلى عنوان يخص البرنامج. جهّزنا مستقبلًا محليًا في `webhook_receiver.py`، لكنه لا يرسل أي رد حتى الآن.

شغّل تجربة للمنطق الداخلي ببيانات وهمية فقط؛ هذا الأمر لا يفتح منفذ شبكة ولا يتصل بـMeta:

```powershell
python webhook_demo.py
```

سترى أربع نتائج: `GET verification logic` للتحقق من الرمز، و`Signed POST payload logic` للتحقق من توقيع الرسالة، و`Duplicate handling` حتى لا نكرر معالجة الرسالة، و`Invalid signature rejected` لرفض طلب غير موثوق. لا تحتاج في هذا الدرس إلى إدخال أي مفتاح حقيقي أو رقم هاتف.

هناك ثلاثة أشياء مختلفة: `Access token` يُستخدم لاحقًا لإرسال رسالة عبر API؛ و`Verify token` كلمة تختارها أنت ليتأكد Meta من عنوان `Webhook`؛ و`App secret` يُستخدم للتحقق من توقيع الأحداث الواردة. لا تضع أيًا منها في المحادثة أو في ملفات المشروع. الربط الفعلي مع Meta يحتاج عنوان HTTPS عام، لأن `localhost` لا يمكن لـMeta الوصول إليه. سنضيف هذا الربط بعد نجاح التجربة المحلية. [مرجع Meta لاستقبال الرسائل](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/receivingMessages/).

إذا نجحت تجربة المنطق، يمكنك اختبار طلبات HTTP الحقيقية على جهازك **دون اتصال بـMeta**:

```powershell
python webhook_http_demo.py
```

يبدأ هذا البرنامج خادمًا مؤقتًا على `127.0.0.1` ومنفذ عشوائي، ويرسل له طلبات اختبار وهمية، ثم يغلقه. لا يستخدم مفاتيح حسابك ولا يفتح عنوانًا عامًا على الإنترنت.

## Lesson 3: تشغيل المستقبل الحقيقي محليًا

افتح `App settings → Basic` في لوحة Meta. سترى `App secret` مخفيًا وبجانبه `Show`. هذا **ليس** `Access token` الذي ظهر في صفحة الاختبار. في نافذة PowerShell شغّل:

```powershell
python webhook_receiver.py
```

عند أول تشغيل، اضغط `Enter` ليولّد البرنامج `Verify Token`، واحفظه في مكان خاص لتستخدم القيمة نفسها في إعداد Meta وعند إعادة تشغيل الخادم. ثم أدخل `App secret` في السؤال التالي؛ الإدخال مخفي ولا يُحفظ في ملف. اترك النافذة مفتوحة. لا ترسل أيًا من هاتين القيمتين في المحادثة أو صورة شاشة.

هذا الأمر يشغّل خادمًا على `127.0.0.1:8000` فقط. تصل إليه Meta عبر نفق HTTPS بعد ضبط `Callback URL`. تم التحقق من استقبال `messages` التجريبية في جلسة التعلم، لكن عند إعادة تشغيل `ngrok` قد يتغير عنوانه ويجب تحديثه في Meta. لا يرسل هذا الخادم ردود WhatsApp تلقائيًا.

للتأكد من أنه يعمل، **اترك نافذة PowerShell التي تشغّل الخادم مفتوحة** ثم افتح `http://127.0.0.1:8000/health` في المتصفح. يجب أن تظهر `OK`. فتح `/webhook` دون بيانات تحقق سيعرض `403` عن قصد؛ هذا لا يعني أن الخادم معطل.

## Lesson 4: صياغة الرد على استفسار عميل

الـWebhook أثبت أنه يستقبل الرسالة ويقرأها. أضفنا الآن منطق محادثة بسيطًا في `chat_flow.py`: يبدأ بسؤال الاسم، ثم نوع المشروع، ثم التفاصيل. إذا كانت الإجابة `not sure` أو `I don't know`، يطرح سؤال توضيح مختلفًا **مرة واحدة** ثم يسجّل `Not provided` ويتابع. بعد اكتمال الأسئلة يظهر ملخص لسليم. إذا أرسل العميل تفصيلًا إضافيًا بعد ذلك، يُضاف إلى الملخص دون إعادة الأسئلة.

للتجربة دون Meta أو مفتاح API، افتح نافذة PowerShell جديدة داخل هذا المجلد وشغّل:

```powershell
python chat_flow_demo.py
```

اكتب بالتتابع مثلًا `Hi` ثم `Alex Morgan` ثم `website` ثم `A restaurant website with a booking form`. سيظهر `Draft reply (not sent)` بعد كل رسالة، وفي النهاية يظهر `Inquiry summary for Salim (local only)`. اكتب `/exit` للإغلاق.

إذا كتب الشخص طلب طعام واضحًا مثل `I need to order 2 burgers and fries`، يرد البرنامج بمزحة خفيفة **مرة واحدة**، يوضح أنه لا يبيع الطعام، ويذكر أن سليم يبني مواقع وتطبيقات، ثم يسأل هل المقصود مشروع موقع أم مطعم. لا يحفظ الطلب كاسم العميل. إذا تكرر طلب الطعام، يعطي توضيحًا مباشرًا بلا مزحة أو سؤال متكرر. وإذا كتب `web` أثناء سؤال الاسم، يحفظ نوع المشروع `website` لكنه يواصل طلب الاسم. الكلمات العامة مثل `reservation` لا تُعامل تلقائيًا كاسم. ورسالة مجاملة مثل `thank you` أو `thanke you` تحصل على رد مهذب ولا تُضاف إلى متطلبات المشروع. هذه حواجز بسيطة لتجنب أخطاء المثال، وليست فهمًا شاملًا لكل لغة أو نية؛ عند الغموض يحتاج النظام إلى توضيح أو مراجعة بشرية.

عندما تعيد تشغيل `webhook_receiver.py`، سيعرض `Draft reply (not sent)` لرسائل WhatsApp التجريبية التي تحمل رقم مرسل. **هذه مسودة محلية فقط؛ لا تصل إلى العميل بعد.** التطبيق غير المنشور قد يتلقى فقط أحداث الاختبار من لوحة Meta؛ لا تفترض أن رسالة عميل حقيقي ستصل قبل استكمال متطلبات النشر.

## Lesson 5: فهم أذكى للرسائل (تجربة محلية)

يستخدم `smart_flow.py` نموذج Claude عبر Anthropic API لفهم نية الرسالة واستخراج المعلومات المحتملة. ثم يتحقق البرنامج من أن كل معلومة موجودة فعلًا في نص العميل قبل حفظها. لا يضع الرسالة تلقائيًا في خانة الاسم أو الخدمة لمجرد أنها جاءت بعد سؤال. إذا لم تتضح الإجابة بعد سؤال توضيحي واحد، يوقف الأسئلة ويمرر الحالة إلى سليم دون إنشاء ملخص عميل وهمي. طلب الطعام يحصل على رد لطيف مرة واحدة، ولا يصبح طلبًا حقيقيًا.

لتجربة هذه النسخة، يجب أن يكون لديك `ANTHROPIC_API_KEY` **صالح**. احصل عليه من `Claude Console → API keys → Create key`، ولا تكتبه في المحادثة أو في ملفات المشروع. افتح نافذة PowerShell جديدة واستخدم الأمر التالي؛ سيطلب المفتاح بإدخال مخفي ويضعه في هذه النافذة فقط:

```powershell
$env:ANTHROPIC_API_KEY = [System.Net.NetworkCredential]::new("", (Read-Host "Anthropic API key" -AsSecureString)).Password
python chat_flow_demo.py --smart
```

يمكنك تجربة `Hi`، ثم `I need to drink some water`، ثم `mai`، `same`، `a`. يجب ألا يظهر `Inquiry summary`. بعد `/exit` أعد التجربة مع `I need a restaurant website with an online reservation form` ثم اسم مثل `Alex Morgan`؛ هذه المرة يمكن إنشاء ملخص فقط إذا فهم النموذج الرسائل بوضوح. كل رد يظهر على أنه `Draft reply (not sent)` ولا يُرسل إلى WhatsApp.

في الوقت الحالي يبقى `webhook_receiver.py` على القواعد القديمة افتراضيًا حتى نراجع سلوك النسخة الذكية في التجربة المحلية. بعد التحقق يمكن تشغيله في وضع الذكاء الاصطناعي بإعداد `ASSISTANT_MODE=smart` في بيئة التشغيل قبل بدء البرنامج. لا ترسل رسائل تلقائية للعميل من هذه النسخة.

إذا كانت نافذة `chat_flow_demo.py --smart` مفتوحة وقت تعديل الملفات، اكتب `/exit` ثم شغّل الأمر من جديد؛ النسخة الجارية لا تعيد تحميل الكود تلقائيًا. عالجنا توقف بعض الردود عند `max_tokens` أو عندما يعيد Claude كتلة `thinking` قبل النص. إذا فشل طلب آخر، يظهر `Local diagnostic` باسم الخطأ فقط، دون عرض المفتاح أو نص الاستجابة الحساسة.

أضفنا حالات تقييم في `promptfooconfig.yaml` لمحادثة البرغر/السعر/صالون الحلاقة، وإجابات الماء الغامضة، وطلب موقع واضح. لتشغيلها لاحقًا من النافذة التي تحتوي `ANTHROPIC_API_KEY`:

```powershell
npx promptfoo@latest eval -c promptfooconfig.yaml --no-progress-bar
```

هذه الاختبارات ترسل رسائل **مصطنعة** إلى Anthropic API وتستخدم رصيد API. تتضمن الآن أيضًا محادثة `reservation app → mo → change my mind → not ok`. ملف `.github/workflows/promptfoo.yml` جاهز إذا أصبح هذا المجلد مستودع GitHub وأضيف مفتاح `ANTHROPIC_API_KEY` ضمن `Repository secrets`. لم تُشغّل اختبارات Promptfoo الحية بعد في هذه الجلسة؛ اختبارات Python المحلية اجتازت 25 حالة.
